# 对拍

中文名：**对拍** · 前缀 `duet` · 端口 **7800**

## 骨架（新骨，不是闸对/缝包换皮）

**左轨装载 → 右轨装载 → 同键对齐落差 → 单边悬账 → 对拍结论**

| 对比 | 闸对 | 缝包（已弃） | **对本仓** |
| --- | --- | --- | --- |
| 拓扑 | 单流入→在途→成物 | 单流入→在途→成物 | **双轨独立装载→键对齐** |
| 在途态 | 开腿账 | 拼缝账 | **无开腿/拼缝；悬账是对齐后单边** |
| 产物 | 行程账 | 整件账 | **对齐差 + 对拍结论** |
| 旁路名 | 旁路匣 | 旁路匣 | **悬账单（命名与语义都不同）** |

皮：支付渠道回执 vs 核心记账。去皮：**双源键对齐管道**。禁止做成收银 CRUD、报表看板、工单系统。

## 同键多笔汇总（已落主链）

双源入库后的键对齐编排。跑对齐前须择定形态，差表键粒度与流水同票：

- **形态甲 `汇总`（折叠）**：同键金额先加总再比，对齐差一键一行。
- **形态乙 `逐笔`（展开）**：按事件编号逐笔物化对照，改写「对齐差物化」包、键下多行；读集合按物化包回读，与汇总口径不同。

同键左两笔右一笔：汇总 1 行、逐笔 2 行；单笔双边两形态均 1 行。补装与对齐并发由 `BEGIN IMMEDIATE` 串行化，不得双写差行或出现双粒度。

只读接口：`GET /api/同键多笔/形态`、`GET /api/同键多笔/粒度`（业务键/左笔数/右笔数/差行数/形态标记/valid）、`GET /api/同键多笔/物化[/<包>]`；择形 `POST /api/同键多笔/形态`，跑对齐 `POST /api/对齐/跑 {"形态":"汇总|逐笔"}`。
